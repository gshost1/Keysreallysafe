            How Keys works

            Getting started

            1. Add a key. Use Add key in the toolbar. The value you type is stored in the macOS Keychain and is not written to a file in this repo. The key list shows names, never values; adding, copying or revealing a key shows it for that action alone, and reading one back asks for Touch ID every time, with the login password fallback macOS offers.
            2. Use it from a tool. Keys can hand the value to one child process as an environment variable, or route a tool through the local gateway with a scoped grant: one key, one host, a method and path scope, an expiry. A grant dies on screen lock, revoke, expiry, gateway off or restart. You do not need a .env file, and nothing is written to your shell profile.
            3. Wire up a coding agent. has the exact commands for Claude Code, Codex, Grok and Droid: the agent talks to the local gateway with a token, and the secret never leaves the vault. keys setup <agent> --key <key> writes the agent's own config (no secret in it), and keys agent <agent> <key> launches it on one Touch ID.
            4. Watch it, revoke it, remove it. The Chart pane's API keys scope shows the calls the local gateway routed — only those; a provider called directly from somewhere else is not observable here. In Keys you can revoke a grant or a client token and delete a key from this vault; the credential itself is revoked with the provider that issued it. The Subscriptions scope is a separate ledger: what Claude Code, Codex and Grok wrote to their own logs on this Mac.

            Use with coding agents

            1. Put keys on your PATH. The app and the command line are one program. Keysrs menu → Install Command Line Tool… links ~/.local/bin/keys to the app; add ~/.local/bin to your shell's PATH if it is not there. Check it:
              keys --help
            2. Add a key. Add key in the Keys pane, or from the terminal; the value is typed at a hidden prompt and goes straight to the Keychain, never to a file.
              keys add work-anthropic --provider anthropic
            3. Connect an agent. Claude Code needs no setup; Codex, Grok and Droid get their own config written once by keys setup (no secret in it). keys agent launches the agent on one Touch ID with a grant that is revoked when it exits. Settings → Agents shows these with your key names.
              keys agent claude work-anthropic
              keys setup droid --key work-anthropic keys agent droid work-anthropic -- droid
              keys setup codex --key router --model <model id> keys agent codex router -- codex
            4. Anything else gets a token, not the key. For one task, a grant: short-lived, one Touch ID, scoped to methods and paths (paths are relative to the provider's prefix, so --paths /messages; /v1/messages means the same). For a program you keep, a client token that lives for days and is revoked from the Keys pane.
              keys grant work-anthropic --task "run evals" --minutes 60 --methods POST --paths /messages
              keys client issue work-anthropic --label "my script" --days 30
              Either token goes where the SDK expects the API key, and the gateway's URL replaces the provider's host; the real key is swapped in on this Mac and never leaves it.
              export ANTHROPIC_BASE_URL=http://127.0.0.1:12767/work-anthropic export ANTHROPIC_AUTH_TOKEN=<token>
            5. From the cloud. A machine you can ssh to gets the gateway through keys tunnel user@host. A managed agent that takes no ssh (GitHub Actions, a Claude Code or Codex cloud session, Modal, E2B) reaches it through a small Worker you deploy in your own Cloudflare account (Relay/ in the repo, docs/relay.md): the Mac keeps one outbound connection to it, every call still lands in this gateway, and the Worker never sees a key.
              keys relay setup --url https://keysrs-relay.<you>.workers.dev keys relay
              The agent then uses https://<your worker>/work-anthropic as the base URL with its client token.

            Figures are shown in tokens and requests by default. Choose USD in the chart's unit chips, on the Usage summary line, or above the Keys table to price them from this repo's list-price table — an estimate, never an invoice. Cached input is counted on each request that reads it again.

            Product analytics

            Share this Mac's daily usage totals and get a Compare line on the Usage page: how your typical day stacks up against everyone who shares. A daily report contains feature-use counts; tokens and prompt counts per tool (Claude Code, Codex, Grok), provider and public model name; gateway request and token totals per provider; and how high each plan window got. It also includes the app version, macOS major version, architecture, the UTC date and a random report ID. It never includes prompts, responses, keys or key names, project or session names, file paths, account IDs, dollar amounts or exact times. A model or provider name that is not a public one is sent as "unknown" or "other".

            Reports send only after you enable this setting, and never include usage from before you did. While it is on, Keys also downloads the shared comparison table once a day from the same server; that request carries nothing about you. Daily summaries are sent after their UTC day ends while the app is running. Failed uploads retry, with up to seven unsent days retained. The collector retains received reports for 30 days. Keys has no persistent device or user ID. Previously sent reports cannot be recalled; turning off discards unsent reports, though a report already in flight may already be received.
