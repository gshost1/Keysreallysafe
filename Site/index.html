Cloud VMs and agents

Your VMs get a dummy key.
The real one never leaves.

A VM, a GitHub Actions job or a cloud coding session can't reach your Mac's loopback. Deploy the small relay Worker into your own Cloudflare account and it can. keys wrap rewrites a project's .env so every provider key becomes a dummy token and a URL at your Worker.

  1. Wrap the env file.One Touch ID. The real keys go into the Keychain; the file gets dummy tokens and your Worker's URL, and the original is backed up beside it.
  2. Ship the file.Copy it to the VM, the Actions secret, the cloud session. Nothing in it works without your Mac.
  3. Calls come home.Each call reaches your Worker, rides one WebSocket your Mac opened, gets the real key swapped in on loopback and goes to the provider. It lands in your usage chart like any other.

If a dummy key leaks.

It can call that one provider, through your Mac, until you revoke it or it expires. The real key is unchanged, so there is nothing to rotate.

  • One key, one hostA token is bound to one vault key and its provider.
  • Expires on its own30 days by default, a year at most. keys client revoke ends it now.
  • Only while your Mac is onNo Mac, no gateway, no calls.
  • Every call countedEach one is a row in your usage. Request bodies never are.

The Worker is a pipe.

You deploy it from the repo into your own account and can read every line. The free Workers plan is enough, and Keysrs hosts nothing.

  • Never sees a keyThe swap happens on your Mac. The Worker carries requests and answers.
  • Holds one secretThe relay secret only lets your Mac connect. It is never a stand-in for a token.
  • Your Mac has to be onOff or asleep, nothing is served: a call waits up to a minute for the Mac, then gets a retryable 503.
  • Cloudflare only, for nowOne Worker with a SQLite-backed Durable Object. The protocol is in the repo; other routes are welcome.

Key vault

Tell Claude the key's name.
Touch ID does the rest.

No copying, no pasting, no .env files. Your agent asks Keysrs by name, you touch the sensor, and it gets a short grant for that one task. It never sees the key.

Your data stays on your Mac

  • Dashboard and API bind to 127.0.0.1 only.
  • The relay is the one optional connection out: your Mac dials a Worker you deployed, and keys never go over it.
  • No account, no sign-up, no license check.
  • Optional “share to compare” is off by default. Turned on, it sends daily usage totals per tool and public model, never prompts, keys, key or project names, paths or device IDs.

No scraping, no borrowed logins

  • Never opens provider websites, cookies or browser sessions.
  • Never reads other tools' auth files.
  • Claude limits come from Claude Code's own /usage, with no model request.

Secrets stay secret

  • Key values never touch the database, a log, the page or the key-list API.
  • Gateway request bodies never reach the usage catalog.
  • Every read of a secret asks for you. Every time.

Questions

Which tools does it read?

Claude Code, OpenAI Codex CLI and Grok CLI, from the session logs and usage caches they already keep in your home folder. Anything else shows as not tracked with a link to that provider's dashboard.

Does it need my provider passwords?

No. It reads files your tools already wrote and never touches their login or auth files. For the vault you paste an API key once; it comes out only after Touch ID.

How does a VM get a dummy key?

Run keys wrap on the project's env file with your Worker's URL. After one Touch ID, every provider key in it is in the Keychain and the file holds a dummy token plus a base URL at your Worker. Copy that file to the VM. Each call goes Worker, your Mac, provider, with the real key added on your Mac. The gateway forgets its keys when Keysrs quits; keys gateway on brings one back after a relaunch.

What if my Mac is off?

Nothing is served. A call that arrives while the Mac is away waits in the Worker for up to a minute, then gets a 503 marked retryable. Sleep doesn't turn the relay off: it redials when the Mac is awake again, and the waiting calls follow. Keep Mac Awake for Relay Calls, off by default, holds off idle sleep while a call is open.

Does the Worker see my keys?

No. It is a pipe you deploy from the repo into your own Cloudflare account; Keysrs hosts none. It holds one relay secret that lets your Mac connect, carries requests and answers, and never has a provider key. If a dummy key leaks, it works for that one provider through your Mac until you revoke it or it expires, 30 days by default, and the real key is untouched.

Why Cloudflare only?

It's the one host the relay knows today: a Worker with a SQLite-backed Durable Object, which the free plan includes. The protocol is documented in the repo, and other routes are welcome.

Is the dollar figure real?

Tokens are real: they're what your Mac measured. Dollars are an estimate from a published list-price table, hidden until you choose USD. Anything unpriced reads as unknown, not $0.

Is it really free?

Yes. Keysrs is MIT-licensed open source with no trial, license key or paid tier.

What Macs does it run on?

macOS 14 Sonoma or newer on Apple Silicon. The download is Developer ID signed and notarized by Apple. No Intel build yet.

How do I install it?

Open the disk image, drag Keysrs to Applications and open it. It adds itself to your login items (Start at Login in the Keysrs menu turns that off) and puts the meter in the menu bar. Closing the window keeps the meter running; ⌘Q quits. Coming from 0.9? Open the new app once: it removes the old background agent and keeps your keys and history.

How does it update?

By itself. Check for Updates in the Keysrs menu finds a newer release, and Update Now downloads it from GitHub, checks its checksum and Apple signature, replaces the app and restarts it. The automatic daily check is off until you turn it on and installs nothing by itself.

How do I uninstall?

Quit Keysrs and drag it to the Trash. To delete your data too, first run keys purge: it deletes the local catalog and every Keychain item the app created, after Touch ID. Nothing is left behind.
