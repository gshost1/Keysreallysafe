Privacy

Effective 2026-11-02. This page describes the app as built; the rules below are enforced in code, and the source is public so you can check.

The short version

Keysrs runs on your Mac. There is no account. We do not receive your prompts, your keys, your usage or your identity. There is no license check and no analytics: the app never contacts us.

What the app reads on your Mac

  • Usage records that Claude Code, OpenAI Codex CLI and Grok CLI write to your home folder (session logs and usage caches). Only counts and metadata are kept; prompt content is not stored.
  • The per-request usage records Droid writes to ~/.factory/logs/: only the [Agent] Streaming result lines of droid-log-single.log and its dated rotations are read, keeping their token counts, model, session id and timestamp. Nothing under ~/.factory/sessions/ is read, and Droid's transcripts, its login files, and every other record in its log (the ones that carry message content) are never opened.
  • Claude's subscription limits, from the cache Claude Code keeps and, when you ask for it, through Claude Code's own /usage command using its existing login. Refreshing in the background every five minutes is off unless you turn it on at first launch or from the menu. No model request is made and no credentials are read.
  • API keys you add yourself. They are stored in the macOS Keychain under your login and are read back only after a Touch ID or login-password prompt.

The app never reads other tools' authentication files (for example ~/.codex/auth.json or ~/.grok/auth.json), never opens provider websites, and never uses browser cookies or sessions.

Update check

The app can check GitHub for a newer release. From version 0.14, Automatically Check for Updates is on unless you turned it off before: once a day the app asks GitHub's public releases API for the latest version number and download address, sending no cookies and nothing from your data. When a newer release exists, it downloads the release's disk image from GitHub, checks its checksum and signing identity, and installs it once the Mac is idle and nothing is waiting on you. With the setting off, nothing is checked or downloaded unless you choose Check for Updates and then Update Now. GitHub, not us, receives the request and the download under GitHub's privacy statement.

What stays on your Mac

  • The usage catalog (an SQLite database in Application Support) holds counters and metadata only. Key values never enter it. Gateway request bodies never enter it.
  • The dashboard and its API bind to 127.0.0.1 only and are not reachable from other machines.

Analytics in earlier versions

Versions up to 0.14.1 had an optional "share to compare" setting, off unless you turned it on, that sent daily aggregate totals to analytics.keysrs.com. Later versions remove it, and updating deletes the setting and any unsent reports from your Mac. The server that received those reports has been shut down and the reports it held were deleted.

This website

Everything above is about the Mac app. This website, keysrs.com, works differently: it uses PostHog (US cloud) for analytics, and what it collects depends on your answer to the banner it shows on your first visit.

Before you answer, or if you say no: page views and a few named events: copying the install command, the download link, the GitHub and star links, and a sign-up on the notify form (that one happened, never the address). Each event carries the kind of device you are on (Mac, Windows, Linux, iPhone or iPad, Android or other), which the page works out in your browser from its user agent, and the ?ref= label of the link you arrived by, if it had one. No cookie and no identity are stored, so each page load counts on its own and you are not recognised on a return visit. Nothing is recorded. The only thing the site keeps in your browser is your answer itself (keysrs-analytics-consent in localStorage), so the banner doesn't ask again. (Our own browsers also hold keysrs-internal, which a private link sets so our visits aren't counted; a visitor never gets it.)

If you say OK:

  • PostHog stores a random visitor ID in a first-party cookie and in localStorage, so a returning visitor counts once and visits can be linked to each other. No name, email or account is attached to it.
  • Your visit is recorded as a session replay: page structure, scrolling, clicks and mouse movement. All text on the page and everything typed into inputs is masked before it leaves your browser, so a replay shows boxes, not words.
  • Page-speed measurements (web vitals) and clicks that did nothing or were repeated in frustration ("dead" and "rage" clicks).
  • Page views and the named events as above.

There is no autocapture of every click and no surveys. You can change your answer at any time: change my choice. Saying no after OK clears the visitor ID and stops recording.

IP addresses are used by PostHog to derive a coarse location and are not stored with events. We are on PostHog's free plan, which keeps session replays for at most 30 days and other events for one year, then deletes them. Fonts load from Google Fonts. There are no other third-party scripts. The site is served by Cloudflare, which logs requests for security and operational purposes under Cloudflare's privacy policy.

Notify-me sign-ups

Keysrs is Mac-only for now, so visitors on other systems can leave an email address to hear when a Linux or Windows version lands. The address, the kind of device you were on and the day you signed up are stored in Cloudflare Workers KV, in our own Cloudflare account. We use the address for one thing: a single email when that version is available. After it goes out, every address is deleted. No newsletter, no other mail, and it is never shared or sold, and it never goes to PostHog.

Your IP address is used only to limit how many sign-ups one connection can send in a minute, and is not stored. To have your address removed sooner, write to support@keysrs.com.
